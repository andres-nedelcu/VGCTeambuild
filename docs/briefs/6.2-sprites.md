# Brief 6.2 — Sprites, cached locally

**Two phases, two models.**
Phase A (coverage check) — **Haiku 4.5**: mechanical, verifiable, no judgment.
Phase B (build) — **Sonnet 5**: needs a fallback design decision.

**Branch:** `feat/sprites`, from `main`.
**Read first:** `docs/briefs/OPERATING_RULES.md`, then `docs/HANDOFF.md` §6.2.

## The constraint that decides the design

`HANDOFF.md` §6.2 left "hotlink vs local cache" open. **It is now closed: local
cache, committed to the repo.**

Andres has two 3-hour flights this weekend and intends to use the tool on them.
Hotlinked sprites give him a broken grid with no network. `data/sprites/` is **not**
gitignored (only `data/raw/*` is), so cached files can and should be committed. A
few hundred gen5 sprites is well under a megabyte.

This also settles it on the merits: local is friendlier, has no runtime dependency
on Showdown's CDN, and the file count is small.

## Phase A — DONE (2026-09-18). Read these results before doing anything.

`scripts/check_sprite_coverage.py` exists and has been run. **221 of 231 formes have
a gen5 sprite.** The full report is at `data/sprites/coverage.json`, keyed
`pokemon_id -> sprite name`.

**The naming rule, which is not what this brief originally said.** Showdown sprite
files are *not* named by `pokemon_id`. They hyphenate the base species from its forme
and concatenate everything after that first separator:

    salamencemega     -> salamence-mega
    charizardmegay    -> charizard-megay      (not charizard-mega-y)
    taurospaldeaaqua  -> tauros-paldeaaqua
    rotomheat         -> rotom-heat

`dim_pokemon.base_species_id` gives this directly — use it, do not munge display
names. Getting this wrong reports ~86 false misses (every Mega, every post-gen5
regional forme) and looks like a catastrophic coverage gap when nothing is missing.

**`HANDOFF.md` §6.2 was too pessimistic.** It warned that Champions-invented formes
"probably do not exist anywhere". Most of them do: `garchomp-megaz`,
`golisopod-mega`, `floette-mega`, `absol-megaz` and `lucario-megaz` all return 200.

**The 10 that genuinely have no sprite**, with their meta rank:

| Forme | Usage | Rank |
|---|---|---|
| Raichu-Mega-Y | 9.6% | **16** |
| Staraptor-Mega | 4.0% | 34 |
| Raichu-Mega-X | 1.8% | 56 |
| Scrafty / Malamar / Pyroar / Eelektross / Dragalge / Barbaracle / Scolipede Megas | ≤0.3% | 99+ |

So the fallback only has to be good for **two** Pokémon. Everything else is below
rank 50 and will essentially never be on screen.

## Phase B — fetch, cache, render (Sonnet)

**Fetcher.** `scripts/fetch_sprites.py`, because **all writes go through `scripts/`**
and the app is strictly read-only (`README.md`, "Rules of the road"). It downloads
into `data/sprites/gen5/<pokemon_id>.png`, skips files already present, and is
idempotent — rerunning must not re-download. Prove that the way this project always
does: run it twice and compare.

**Fallback, for the 10 with no sprite.** The typing question is already answered:

- **Raichu-Mega-X and -Y are both pure Electric, same as base Raichu.** So base
  sprite plus a Mega badge is accurate here, not just convenient. This covers the
  only sprite-less forme anyone will actually see (rank 16).
- **Staraptor-Mega is Fighting/Flying; base Staraptor is Normal/Flying.** This is
  the one case where a bare base sprite would state the wrong types. Rank 34, so it
  will appear at wider slider settings.

A base sprite with a Mega badge is therefore the right default, but it must not be
the *only* signal where typing differs. Decide how Staraptor-Mega reads — a
type-coloured border, a tooltip, or falling through to a type chip instead of a
sprite — and log the choice in `DECISIONS.md`.

**Render.** Sprites go where they earn their place, and the biggest win is named in
`HANDOFF.md` §6.3: threat names on the coverage grid are angled and cramped at 20+
columns, and sprites fix that better than any font tweak. Also consider the threat
list's first column. Use `st.image` or an inline `<img>` from the local file; never
a remote URL.

**Attribution.** Sprites are Showdown's. This is a local personal tool so nothing is
published, but note the source in `DECISIONS.md` — the project already took an
equivalent position for CBD data on 2026-09-16.

## Acceptance criteria

- The app renders every sprite **with the network off**. Test it that way.
- Every forme in the current meta either has a sprite or a deliberate, logged
  fallback that does not misstate its typing.
- `fetch_sprites.py` is idempotent, proven by running twice.
- Cached sprites are committed.
- `uv run pytest -q` green, and you have opened the app and looked.

## Non-goals

Do not restyle the charts — that is brief 6.3, which runs after this one precisely
because sprites change what needs styling. Do not add sprites for all 1,518 dex
entries; only what the meta and the loaded teams use. **No warehouse writes.**
