**Status:** unblocked 2026-10-07. One decision is Andres's and is still open (§2).
**Read first:** `docs/briefs/OPERATING_RULES.md`, `docs/HANDOFF.md` §6.8,
`docs/DECISIONS.md` (2026-09-16 "mixing sources within one species would blend
populations", 2026-09-18 "one source per species").

## 1. Why this is worth building

Every number in the tool today is the **tournament** meta: 159 Limitless events,
8,959 teams. Andres practises on **ladder**, which is a different population playing
a different metagame. The tool is currently confident about a field he is not facing.

The ladder picture is available and it genuinely differs. At cutoff 1630, against the
tournament meta on the same regulation:

| | ladder | tournament | |
|---|---|---|---|
| Rillaboom | 46.0% | 54.3% | −8.3pp |
| Gholdengo | 19.1% | 25.8% | −6.7pp |
| Raichu-Mega-Y | 12.7% | 18.4% | −5.7pp |
| Indeedee-F | 20.9% | 16.6% | +4.3pp |
| Basculegion | 19.1% | 15.2% | +3.8pp |
| Golisopod-Mega | 15.9% | 12.6% | +3.3pp |

The pattern is **ladder lags**. Salamence-Mega is 27.1% on ladder against 25.0%
tournament-wide and only ~12.8% in the most recent tournament week; the tournament
risers (Raichu, Garchomp, Volcarona) are all *under*-represented on ladder. So the
ladder view is not merely "the same meta, noisier" — it is the previous meta, still
being played. That is exactly the thing worth knowing before a ladder session, and it
is invisible from the tournament data alone.

### Recommendation: 1630

1630 and 1760 **agree more closely with each other than any other pair in the table**
(mean rank shift 0.95), so 1760 buys almost no change of picture — while costing 22x
the sample, dropping to 13,010 effective teams. At that size the tail is thin enough
that mid-table ordering is noise, and it would be the one view in the tool whose
sample is smaller than the tournament sample it sits beside.

0 is the wrong direction: it is the only cutoff whose top 15 contains Sinistcha and
Whimsicott over Arcanine-Hisui and Raichu-Mega-Y, which is the beginner ladder, not
the field Andres meets. 1500 is defensible and keeps 1.98M teams, but it still carries
Milotic over Raichu-Mega-Y and sits closer to raw than to the skilled ladder.

1630 is the standard Smogon "good player" cutoff, keeps 288,196 effective teams — two
orders of magnitude more than the tournament sample — and reaches the picture that
1760 confirms. **Recommend 1630. Andres's call.**

## 3. What the investigation already settled

These cost real time to establish; none of them need redoing.

- **Species keys resolve cleanly.** All 294 chaos keys map through `vgc.ids.to_id`
  into `dim_pokemon` with **zero unresolved and zero collisions**. No
  `id_aliases.yaml` work is needed, which was the main feared cost.
- **Mega formes are native.** Smogon keys them separately (`Salamence-Mega`,
  `Raichu-Mega-Y`), so the ladder source arrives already at `mart_meta_top`'s forme
  grain. None of the stone-share splitting in `02_meta_top.sql` applies to it, and
  none of its known approximations are inherited.
- **The usage grain matches Limitless exactly.** `sum(usage)` is 5.998–6.000 at every
  cutoff, so Smogon's `usage` is the share of *teams* holding the species, which is
  `meta_usage`'s definition. The two sources are directly comparable as numbers — the
  difference is purely population, which is the whole point.
- **`Raw count` is not cutoff-filtered.** It barely moves across the four files
  (22.13M → 22.04M), so only `usage` is reweighted. Do not use `Raw count` to derive
  a per-cutoff sample size, and do not use `number of battles` either (§2).
- **The schema already fits.** `fact_usage` and `fact_usage_detail` both carry
  `source` in the primary key and already document `'smogon'` as a value. No DDL.
- **`format_ids.smogon` is already configured** as `gen9championsvgc2026regmc` in
  `config/regulations.yaml` and is correct.

## 4. The constraint that shapes the design

**Smogon publishes monthly.** A chaos file is one calendar month, with no finer
dimension inside it. That has consequences worth stating before any code:

1. **`since` cannot apply to the ladder source at all.** The tournament side now
   spans 27 days of genuine meta movement and `since` has become its most important
   filter — but there is no ladder equivalent. A side-by-side view must not imply the
   two windows match.
2. **The 2026-09 file is itself an average over the month the meta turned over.**
   Part of the "ladder lags" gap in §1 is real lag and part is the monthly average
   including early September. Both the brief and the UI should say so rather than
   presenting the gap as pure population difference. The 2026-10 file, published in
   early November, will be the first clean read.
3. `snapshot_date` should be the month, and the label should say "2026-09, whole
   month" — not a day that implies precision the source does not have.

## 5. Design — one source at a time, never blended

`DECISIONS.md` is explicit that mixing sample types is misleading, and the 2026-09-18
entry already dropped a source toggle once when its premise turned out to be false.
This one is different and the premise holds: Smogon *does* publish a species ranking,
so there is something real to toggle between.

**The rule: a source selector, never a blend.** No averaging, no "combined" view, no
weighting one into the other. The selector sets which source every meta number on the
page comes from, and the caption says which one is showing and over what window.

- `fact_usage` gains rows with `source = 'smogon'`; nothing existing changes.
- `meta_usage` and everything built on it stay **tournament-only**. The ladder source
  gets its own path rather than a `source` parameter threaded through the macro, so
  there is no code path in which the two can be summed by accident.
- The build-data marts (`mart_build_detail` and the Speed/Scarf shares that read it)
  stay CBD-preferred and untouched in this phase. Smogon's `Items`/`Moves`/`Spreads`
  are a tempting second opinion there too, but that is a separate decision with its
  own one-source-per-species rule, and it is **out of scope here**.

### Steps

1. `src/vgc/ingest/smogon.py` — fetch one `{format}-{cutoff}.json` to
   `data/raw/smogon/{regulation}/{YYYY-MM}/`, manifest written last, mirroring
   `championsbattledata.py`'s resume-and-manifest shape.
2. `scripts/fetch_smogon.py` — thin CLI over it, `--month`, `--cutoff`.
3. `scripts/load_smogon.py` — `fact_usage` rows with `source='smogon'`, species via
   `to_id`, `sample_size` = the derived weighted team count from §2, not
   `number of battles`. Delete-then-insert per (source, regulation, month) so it is
   idempotent; **prove it by running twice**.
4. Refuse to load a file whose `info.cutoff` differs from the configured
   `smogon.rating_cutoff`. This is what makes "never mix" mechanical rather than a
   note in a doc — and it is the single most important line in the brief.
5. Wire into `refresh.py` as an optional fetch step, alongside CBD.
6. `vgc.freshness.sources` gains a Smogon row, labelled with the month.
7. UI: source selector, plus the window caveat from §4.

### Tests worth writing

- Every chaos species key resolves (the §3 finding, pinned so a future file that
  breaks it fails loudly rather than silently dropping species).
- `sum(usage)` is within tolerance of 6.0 — this is what licenses comparing the two
  sources at all, so it should fail if Smogon ever changes the convention.
- The cutoff guard in step 4 rejects a mismatched file.
- Loading twice leaves the row count unchanged.
